3 — Audition the actual export mix (Q1 · Q8 engine features) & transport integration
Default design — the master strip The panel footer is a master strip: MIX meter + CLIP readout + a prominent “Audition export mix” button. Audition renders the true offline mix (media::AudioMixer sum — the exact buffer the encoder muxes, Q8 legitimizes the engine work) and plays it from the playhead; the row meters then show PER-TRACK contributions into that sum, not independent QMediaPlayer output. While auditioning, per-track preview players are muted and the strip turns active (neutral fill — accent stays reserved for the playhead).

7 — Open conflicts, reported not resolved
CONFLICT 1 (Q5 internal tension): “end ≥ start at the control” and “0 = to end” cannot both hold literally when start > 0 (0 < start). The mockup exempts the sentinel (0 renders as “to end”, never clamped) — one interpretation, needs confirmation. The inventory compounds it: getValidAudioStreams requires a “non-empty window” (AudioPlaybackWidget.h:103) and syncTracks reads a half-open [startFrame, endFrame) — both read end=0 as EMPTY, opposite to AudioMixer.h:21. CONFLICT 2 (Q1 × export surfaces): “the actual export mix” is ambiguous when the export dialog’s “Export with audio” is OFF or the destination can’t carry audio (containerCarriesAudio, GIF/sequences — §C/§E): the actual export then has NO audio. The mockup defines Audition as the track-level export mix (export-enabled tracks) and flags this; whether Audition should mirror the pending dialog/destination state is NOT settled by any answer. CONFLICT 3 (Q1 × Q4): for a gapped selection the export audio is per-range concat (R12); which range Audition renders — full timeline, current selection, or the export dialog’s range — is nowhere specified (the strip shows “range 0–360” as a placeholder readout). CONFLICT 4 (Q7 scope gap): inline per-row errors cannot express file-scope failures (JSON parse error, deserialize failure) nor C2’s overwrite confirmation (§A lists it as a modal). §5 F1/F2 shows both readings; the overwrite-confirm dialog is likewise unaddressed by the answers. CONFLICT 5 (Q8 creep, minor): the §3 “Mixing… 1 of 2 tracks decoded” progress assumes decode-level progress reporting that AudioMixer does not expose today (mix() is one-shot, G4); permissible under Q8 but it is an engine addition beyond “expose existing capability”.
